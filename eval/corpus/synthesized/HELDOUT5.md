# Fifth set of held-out GPU query operator tasks

You write GPU kernels for a columnar query engine that runs on NVIDIA GPUs (RTX A6000, sm_86, CUDA 13.0). Columns live in device memory as flat arrays in the Apache Arrow layout. Write each kernel the way you would for a production engine: correct on every input size, including 0 and sizes that are not a multiple of the block size, and fast.

Write every task three times, in the task's directory:

- `numba.py`: a Numba CUDA kernel (`from numba import cuda`). Define the kernel as a plain Python function named `kernel` decorated with nothing, a module-level `TYPES` tuple of Numba types for `cuda.compile_ptx`, and a function `run(...)` that launches `cuda.jit(kernel)` on device arrays with 256 threads per block. Arrays are 1-D Numba arrays (`float64[:]`, `int32[:]`, and so on).
- `kernel.cu`: a CUDA C++ kernel `extern "C" __global__ void kernel(...)` with raw pointers and scalar arguments, launched with 256 threads per block, plus a separate `test.cu` with a `main` that allocates inputs, launches the kernel, and checks the result against a CPU reference.
- `triton.py`: a Triton kernel `@triton.jit def kernel(...)`, followed by any `tl.constexpr` arguments, such as a block size. Define at module level `TYPES`, a dict from each argument that is not a `tl.constexpr` to its Triton type (`"*fp64"`, `"*i64"`, `"*i32"`, `"*u32"`, `"*i8"`, or `"*u8"` for a pointer to that element type, and `"i64"` for a scalar); `CONSTANTS`, a dict from each `tl.constexpr` argument to its value; `NUM_WARPS`, the number of warps of each program; and `run(...)`, which launches `kernel[grid](...)` with `num_warps=NUM_WARPS` on PyTorch CUDA tensors.

Each task lists the kernel's arguments in order. Every version takes them in that order and with those names. Scalars are `int64`.

For each task directory, also write `signature.json`: one entry per kernel argument, in order, with the fields `name`, `kind` (`"input"`, `"output"`, `"inout"`, or `"scalar"`), `dtype`, `length` (an expression over the other arguments' names, for example `"n"` or `"g + 1"`; for scalars, the value range as `"[lo, hi]"` or a meaning such as `"rows of keys"`), and `indexes_into` (the name of the array whose positions this argument's values denote, or null).

Test every kernel on the GPU against a NumPy reference, with n in {0, 1, 1000, 1000003}: the Numba kernel in `test_numba.py`, the CUDA kernel in `test.cu`, and the Triton kernel in `test_triton.py`. Record in `NOTES.md` any task you could not complete and why.

## Tasks

1. `between_bitmap(values, valid, out, n, lo, hi)`: `values` (int64, n), `valid` (uint8, `(n + 7) / 8` bytes) is the Arrow validity bitmap of `values`: row `i` is valid when bit `i % 8` of byte `i / 8` is 1, the least significant bit first. Output `out` (uint8, `(n + 7) / 8` bytes), an Arrow bitmap in the same layout. `n` is in `[0, 2^30]`, and `lo` and `hi` are any int64 values. Bit `i` of `out` is 1 when row `i` is valid and `lo <= values[i] <= hi`, and 0 otherwise; the bits of the last byte at positions `n` and above are 0.
2. `gather_strings(offsets, chars, idx, out_offsets, out_chars, n, m)`: a string column as `offsets` (int32, n + 1; nondecreasing, `offsets[0] = 0`) and `chars` (uint8, `offsets[n]` bytes), `idx` (int32, m; every value a row of the string column, in `[0, n)`), `out_offsets` (int32, m + 1; `out_offsets[0] = 0` and `out_offsets[i + 1] = out_offsets[i] + offsets[idx[i] + 1] - offsets[idx[i]]`), output `out_chars` (uint8, `out_offsets[m]` bytes). `n` and `m` are in `[0, 2^30]`, and `offsets[n]` and `out_offsets[m]` are at most `2^31 - 1`. Write the bytes of string `idx[i]` to `out_chars[out_offsets[i] : out_offsets[i + 1]]`, so that `out_offsets` with `out_chars` is the gathered column.
3. `group_sum_valid(group, value, valid, counts, sums, n, g)`: `group` (int32, n; every value in `[0, g)`), `value` (int64, n), `valid` (uint8, `(n + 7) / 8` bytes) is the Arrow validity bitmap of `value` in the layout of task 1, output `counts` (int64, g; zero on entry), output `sums` (int64, g; zero on entry). `n` is in `[0, 2^30]` and `g` is in `[1, 1024]`. `counts[k]` becomes the number of valid rows with `group[i] = k`, and `sums[k]` the sum of `value[i]` over those rows, computed modulo 2^64 in two's complement, so that an overflow wraps around. The null rows count toward neither.
4. `asof_join(left, right, out, n, r, tolerance)`: `left` (int64, n), `right` (int64, r; sorted ascending), output `out` (int32, n). `n` is in `[0, 2^30]`, `r` is in `[0, 2^30]`, every value of `left` and `right` is in `[-2^61, 2^61]`, and `tolerance` is in `[0, 2^62]`. `out[i]` is the largest row `j` of `right` with `right[j] <= left[i]` and `left[i] - right[j] <= tolerance`, or -1 when there is none.
5. `decimal_rescale(values, out, overflow, n, shift)`: `values` (int64, n), the unscaled values of a decimal64 column, output `out` (int64, n), output `overflow` (int8, n). `n` is in `[0, 2^30]` and `shift` is in `[-18, 18]`. For `shift >= 0`, `out[i] = values[i] * 10^shift` when the product is in the int64 range, and `overflow[i] = 0`; otherwise `out[i] = 0` and `overflow[i] = 1`. For `shift < 0`, `out[i]` is `values[i] / 10^(-shift)` rounded to the nearest integer, with a tie rounded away from zero, and `overflow[i] = 0`.
6. `string_hash(offsets, chars, out, n)`: a string column as `offsets` (int32, n + 1; nondecreasing) and `chars` (uint8, `offsets[n]` bytes), output `out` (uint32, n). `n` is in `[0, 2^30]`. `out[i]` is the 32-bit FNV-1a hash of the bytes of string `i`: start from `h = 2166136261`, and for each byte `c` in order set `h = (h ^ c) * 16777619` modulo 2^32. The empty string has the hash 2166136261.
7. `bitmap_slice(source, out, n, offset)`: `source` (uint8, `(offset + n + 7) / 8` bytes), an Arrow bitmap in the layout of task 1, output `out` (uint8, `(n + 7) / 8` bytes). `n` is in `[0, 2^30]` and `offset` is in `[0, 2^30]`. Bit `i` of `out` is bit `offset + i` of `source` for `i` in `[0, n)`, and the bits of the last byte of `out` at positions `n` and above are 0, as for slicing an Arrow column at row `offset`.
8. `join_materialize(build, probe, offsets, out_build, out_probe, b, p)`: `build` (int64, b; sorted ascending), `probe` (int64, p), `offsets` (int32, p + 1; `offsets[0] = 0`, and `offsets[i + 1] - offsets[i]` is the number of elements of `build` equal to `probe[i]`), output `out_build` (int32, `offsets[p]`), output `out_probe` (int32, `offsets[p]`). `b` and `p` are in `[0, 2^30]`, and `offsets[p]` is at most `2^31 - 1`. If the elements of `build` equal to `probe[i]` are the rows `f` to `f + c - 1`, write `out_build[offsets[i] + j] = f + j` and `out_probe[offsets[i] + j] = i` for each `j` in `[0, c)`.
9. `add_months(days, months, out, n)`: `days` (int32, n; days since 1970-01-01 in the proleptic Gregorian calendar), `months` (int32, n; every value in `[-120000, 120000]`), output `out` (int32, n). `n` is in `[0, 2^30]`; every date of `days`, and every month that `days[i]` plus `months[i]` months reaches, is in the years 1 to 9999. `out[i]` is the date `months[i]` months after `days[i]`, with the same day of the month, or the last day of the target month when that month is shorter.
10. `argmin(values, row, n)`: `values` (int64, n), output `row` (int32, 1 element; -1 on entry). `n` is in `[0, 2^30]`. `row[0]` becomes the smallest row `i` such that `values[i]` is the minimum of `values`, and stays -1 when `n = 0`.
11. `run_end_encode(values, run_ends, run_values, count, n)`: `values` (int64, n), output `run_ends` (int32, n), output `run_values` (int64, n), output `count` (int32, 1 element; zero on entry). `n` is in `[0, 2^30]`. The column consists of `r` maximal runs of consecutive equal values. Set `count[0] = r`, and for run `j` in `[0, r)`, in row order, set `run_ends[j]` to the row after its last row and `run_values[j]` to its value, as in Arrow run-end encoding. The elements of `run_ends` and `run_values` at positions `r` and above stay as they are on entry.
12. `segmented_cummax(values, first, out, n)`: `values` (int64, n), `first` (int32, n; `first[0] = 0`, and for `i > 0`, `first[i]` is `i` or `first[i - 1]`), output `out` (int64, n). `first[i]` is the first row of the partition of consecutive rows that holds row `i`; a partition can be as long as the column. `n` is in `[0, 2^30]`. `out[i]` is the largest of `values[first[i] : i + 1]`.
13. `string_concat(a_offsets, a_chars, b_offsets, b_chars, out_offsets, out_chars, n)`: two string columns of n rows each, as `a_offsets` (int32, n + 1; `a_offsets[0] = 0`) and `a_chars` (uint8, `a_offsets[n]` bytes), and `b_offsets` (int32, n + 1; `b_offsets[0] = 0`) and `b_chars` (uint8, `b_offsets[n]` bytes), `out_offsets` (int32, n + 1; `out_offsets[i] = a_offsets[i] + b_offsets[i]`), output `out_chars` (uint8, `out_offsets[n]` bytes). `n` is in `[0, 2^30]`, and `out_offsets[n]` is at most `2^31 - 1`. Write string `i` of the first column followed by string `i` of the second to `out_chars[out_offsets[i] : out_offsets[i + 1]]`.
14. `hash_distinct(keys, table_keys, table_rows, n, capacity)`: `keys` (int64, n; every value other than -1), output `table_keys` (int64, capacity; -1 on entry), output `table_rows` (int32, capacity; `2^31 - 1` on entry). `n` is in `[0, 2^29]`, and `capacity` is a power of two in `[1, 2^30]` and at least `2 * n`. Insert each distinct key into an open-addressing hash table with linear probing, starting at slot `h(key) & (capacity - 1)` for `h(x) = (x * 0x9E3779B97F4A7C15) >> 32` computed on the unsigned 64-bit value. Afterward each distinct key of `keys` is in exactly one slot `s`, reached from its start slot by linear probing without passing a slot that holds -1; `table_rows[s]` is the smallest row `i` with `keys[i]` equal to that key; and every other slot holds -1 and `2^31 - 1`.
15. `range_window_sum(ts, values, out, n, range)`: `ts` (int64, n; sorted ascending, every value in `[-2^62, 2^62]`), `values` (int64, n), output `out` (int64, n). `n` is in `[0, 2^30]` and `range` is in `[0, 2^62]`. `out[i]` is the sum of `values[j]` over all rows `j` with `ts[i] - range <= ts[j] <= ts[i]`, which includes the rows after `i` with the same `ts`, as in a SQL `RANGE BETWEEN range PRECEDING AND CURRENT ROW` frame. Compute the sum modulo 2^64 in two's complement, so that an overflow wraps around.
16. `bit_unpack(packed, out, n, w, bits)`: `packed` (uint32, w), output `out` (uint32, n). `n` is in `[0, 2^30]`, `bits` is in `[1, 32]`, and `w` equals `(n * bits + 31) / 32`. The words of `packed` form a bit stream in which bit `p` is bit `p % 32` of `packed[p / 32]`, the least significant bit first. Code `i` is the `bits` bits from position `i * bits` of the stream, with the first of them as its least significant bit; a code can span two words. `out[i]` is code `i`, as when decoding bit-packed dictionary codes in Parquet.
17. `group_argmax(group, value, best, n, g)`: `group` (int32, n; every value in `[0, g)`), `value` (int64, n), output `best` (int32, g; -1 on entry). `n` is in `[0, 2^30]` and `g` is in `[1, 2^20]`. `best[k]` becomes the smallest row `i` with `group[i] = k` whose `value[i]` is the largest value of group `k`, and stays -1 for a group without rows.
18. `fill_forward(values, valid, out, n)`: `values` (int64, n), `valid` (uint8, `(n + 7) / 8` bytes) is the Arrow validity bitmap of `values` in the layout of task 1, output `out` (int64, n). `n` is in `[0, 2^30]`. `out[i] = values[j]` for the largest valid row `j <= i`, and 0 when every row up to `i` is null. A run of null rows can be as long as the column.
19. `timestamp_floor(ts, out, n, unit)`: `ts` (int64, n; microseconds since 1970-01-01 00:00:00, every value in `[-2^62, 2^62]`), output `out` (int64, n). `n` is in `[0, 2^30]` and `unit` is in `[1, 2^40]`, for example 3600000000 for an hour. `out[i]` is the largest multiple of `unit` that is less than or equal to `ts[i]`, so that a timestamp before 1970 is rounded down, toward negative infinity.
20. `string_to_int(offsets, chars, out, valid, n)`: a string column as `offsets` (int32, n + 1; nondecreasing) and `chars` (uint8, `offsets[n]` bytes), output `out` (int64, n), output `valid` (uint8, `(n + 7) / 8` bytes; zero on entry), an Arrow bitmap in the layout of task 1. `n` is in `[0, 2^30]`. String `i` parses when it is an optional `+` or `-` followed by one or more ASCII digits `0` to `9` and nothing else, with any number of leading zeros, and its value is in the int64 range, `-9223372036854775808` included. When it parses, `out[i]` is its value and bit `i` of `valid` is 1; otherwise `out[i] = 0` and bit `i` stays 0.
